三句话：

1. **看得懂** —— 界面上不出现听不懂的缩写。

3. **拿得走** —— 一键导出数据包，丢给 AI 就能写视频脚本。

## 五 两个新字段：让「书」和「预设」进上下文

现状：`runner._system_prompt()` 只发四行（角色 / 简介 / 场景 / 请以角色身份对话）。
→ 用户写的世界书、预设，**在评测里根本不存在**。这是本次要拆的墙。

| 字段 | 是什么 | 装在哪 | 测什么 |
|---|---|---|---|
| `lore` | 资料（设定书） | system prompt 的「背景资料」段 | 记忆：问到的答对 + 资料外的不瞎编 |
| `preset` | 预设（文风规范文本） | system prompt 头部 | 文风：接 vs 不接的差值 |

**双壳跑**：同一张题卡可勾「带预设 / 不带预设」跑两遍，落两组 case，榜单并排显示差值。
**向后兼容**：旧题卡不加字段照常跑。

## 六 格式卡重做：参考角色卡里真会遇到的形态

现在测的是纯数据格式（JSON / 表格 / 代码围栏），跟 RP 卡的真实需求脱节。
重做为**卡格式遵从 v3**——在 RP 对话里同时要求下面这些，逐轮叠加：

| # | 形态 | 判法（全程序化） |
|---|---|---|
| 1 | 正文包 `<maintext></maintext>`，全文只能出现一次 | 标签计数 |
| 2 | 结尾 `<状态栏>` 固定字段模板（日期/时间/地点/好感/状态） | 字段齐全 + 标签配平 |
| 3 | 变量块 `<变量更新><JSONPatch>[…]</JSONPatch></变量更新>` | JSON 可解析 + 结构键齐 |
| 4 | 结尾 3 条 `<选项>` | 计数 |
| 5 | HTML 状态栏（固定 class + 标签配平） | 现有 `html@N` 校验复用 |
| 6 | 第 8 轮仍全守（长对话不掉格式） | 逐轮比对 |

**全部确定性判分，零 LLM 成本，不涉政策红线。**
