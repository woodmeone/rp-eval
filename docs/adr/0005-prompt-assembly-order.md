# 0005 — 提示词装配顺序：预设 → 卡面 → 资料 → 收尾指令

## 背景

I2 之前，发给被测模型的提示词只有三行卡面字段加一句"请以角色身份进行 RP 对话"
（`runner._system_prompt`）。这意味着用户写的世界书与预设**在评测里根本不存在**——
榜单测出的"上限"与玩家真实玩法之间隔着两整层，社区那句"外壳决定上限"在当前工具里不成立。

要补这两层，就必须先定一件事：**它们拼在提示词的什么位置**。位置决定模型注意力权重，
选错了等于白加。

## 决策与取舍

固定顺序：

```
[预设文本]        ← 仅"带预设"外壳；文风总纲，压最前
角色：… 简介：… 场景：…   ← 卡面三行，位置不动
【背景资料】\n[资料]      ← 仅当题卡带 lore
请以角色身份进行 RP 对话。  ← 收尾指令，永远最后
```

三条理由：

1. **预设压最前**。它是"怎么说话"的总纲，属于背景设定性质；放最前符合模型对
   system 消息的常规理解（先立框架，再讲具体）。
2. **资料贴着收尾指令放**。位置越靠后，模型越不容易把它当"可忽略的背景噪音"。
   这与世界书领域那条经验一致：规则与关键知识去尾部，泛用知识去前部。
3. **收尾指令永远最后**。它是唯一一句祈使句，必须离生成最近。

**放弃的方案**：资料放最前（会与预设抢头部，且离生成太远）；
预设与资料合并成一段（两个来源混在一起，出问题无法定位是哪一层导致）。

**回归底线**：无 `lore` 无 `preset` 的旧题卡，拼出来与改动前**逐字节一致**。
加字段不许悄悄改变任何既有 run 的输入，否则历史结论与新结论不可比。这一条有测试写死老字符串比对。

## 后果

- 题卡新增两个可选字段：`lore`（资料）、`preset`（预设）。缺失时行为完全不变。
- 双壳跑：同一题卡可"裸壳 / 带预设"各跑一遍，榜单页给差值。**只有两壳都跑过才算差值**，
  否则显示破折号而不是 0——0 会被读成"预设没用"，那是在替数据编结论。
- `case_key` 升为三元组 `(scene, model, shell)`：少这一维，第二遍会被当"已完成"静默跳过。
- 审查阶梯聚合按 `(model, shell)` 分开：混在一起会把"带预设守住、裸壳崩了"平均成"没崩"。
- 后续若要让世界书支持关键词触发（而非常驻资料），装配顺序仍是这条基线，只是在资料段内部做筛选。
