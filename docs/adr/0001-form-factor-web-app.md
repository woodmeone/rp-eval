# 0001 — 形态：本地 Web 应用（FastAPI + 自写像素风 HTML/JS + SSE），而非 CLI 报告流

## 背景

工具的核心用途是"录屏出视频素材"：测评过程本身要可视化、可交互、有演示感。
原设计方案（账号目录 测评工具设计方案.md）是"静态 HTML 报告 + 素材导出模块"，
2026-10-09 grilling 中用户明确：不要截图导出功能，录屏直接录前端界面；
前端可视化是演示重点，CLI 退化为一条启动命令。

## 决策与取舍

选 **FastAPI 单进程服务 + 自写 HTML/JS（无构建链）+ SSE 实时推送**：
- 一条 `rp-eval` 命令起服务并自动打开浏览器；
- 控制台页跑测评时逐轮判定实时滚动（录屏高潮镜头）；
- 证据浏览器/榜单页为同服务下的静态路由页。

放弃的选项：
- **静态 HTML 报告流**：跑完才能看，无实时流，演示感差；
- **Streamlit/Gradio**：开发最快，但"工具站"长相做不了像素主题，录屏没质感；
- **React SPA**：表现力最强，但引入构建链，违反"单人可维护"红线。

## 后果

- 前端视觉完全可控，与视频世界观一致；
- 无 node_modules、无打包步骤，Python 单仓依赖不变；
- 服务是单用户本地服务，不做鉴权、不做并发多 run（一次只跑一个 run）。
